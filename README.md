# 华山医院（浦东院区）抢号监测器

GitHub Actions 云端每 5 分钟查一次号，出现可约号源（放号新释放 / 他人退号弃号）时，经方糖（Server酱）推送微信提醒。**电脑关机也照常运行。**

三大实战机制（2026-10-15 升级，10-19 增前夜退号窗口）：

1. **放号窗口高频监测**：每日 17:35–18:10（医院晚间放号时段；实测放号后约 5 分钟号源即被抢光，故 18:10 收尾，其后交 5 分钟网格兜底）自动提频到 **1 分钟一轮**，并在 17:55 发【放号预警】请陛下就位——解决「18:00 放号秒光、5 分钟节奏抓不住」的问题；
2. **门诊前夜 20:00 提醒 + 退号高频窗口**：门诊前一天（周一/周三）晚 20:00 推送明日门诊医生清单；并自动进入 **20:00–23:30 约 3 分钟一轮**的高频盯号——他人取消的次日门诊号一般在晚 8 点后放出，专抓这段（6 点那轮是新号放号，两回事）；
3. **平安简报**：12:00 / 18:00 各一条存活确认，区分「真没号」与「监测器断联」。

## 监测对象（仅浦东院区 hospitalid=209）

| 医生 | 科室 | 114 id | 目标班次 | 价格 |
|---|---|---|---|---|
| 齐思思 | 皮肤科 | 56654 | 周二上午 / 周四下午 | 40 元专家门诊 |
| 周丽诺 | 内分泌科 | 45011 | 周四上午 / 周四下午 | 50 元专家门诊 |

## 数据源

114 名医导航移动端**免登录**接口：

```
GET https://m.114-91.com/common/api?cmd=DoctorList&sr=1&keyword=<姓名>&hospitalid=209&ipage=1&pagesize=20&sectiontype=0
```

信号：`remainnum > 0`（剩余可约号数）。响应约 0.1 秒，稳定。

## 配置 Secrets

仓库 `Settings → Secrets and variables → Actions → New repository secret`：

| 名称 | 值 |
|---|---|
| `SERVERCHAN_SENDKEY` | 方糖（Server酱）SendKey（SCT 开头）。微信内「方糖」服务号菜单查。 |

> SendKey 获取（sct.ftqq.com 在手机微信浏览器里跳登录打不开，请勿用网页）：
> **首选**：微信 → 通讯录 → 公众号/服务号 → 搜「方糖」→ 进入 → 底部菜单「我的 / 推送 / SendKey」查 SCT 开头密钥；或翻绑定成功当天方糖发来的推送消息（通常含密钥）。
> 备选网页：`sc.ftqq.com`（旧版，登录后首页显示 32 位密钥）——但旧版与 Turbo 版 SCT 密钥是两套系统，若绑的是方糖 Turbo 版则此键不匹配。

## 手动触发（GitHub 网页 / 手机）

`Actions → huashan-slot-monitor → Run workflow`，可填 `force_remain`、`skip_push`。

## 可靠的触发方式（自建循环版，零外部依赖）

⚠️ **GitHub 原生 `schedule` 对高频（每 5 分钟）定时极不可靠**：实测 10-15 跨约 14 小时仅触发 3~4 次（理应 ~170 次），共享 runner 高峰排队丢任务。

**解法（自建循环）**：workflow 改为「单次 run 内部每 5 分钟自检一轮、连跑约 5.5 小时」，原生定时只负责**重新点火**（两条错峰 4 小时的 cron）。这样即使 GitHub 一天只成功排队 4~6 次，也能铺满约 22~33 小时的每 5 分钟监测——被丢弃的调度由循环时长对冲。

- 单 job 上限 6 小时（GitHub 免费版硬顶），循环设 330 分钟留余量，`timeout-minutes: 350` 兜底。
- `concurrency` 串行不取消：上一轮没跑完，下一轮**排队接力**，跑完无缝续上，不断档。
- 心跳（12:00/18:00【平安简报】）由 monitor.py 在循环内每 5 分钟自检触发，天然覆盖。
- 循环内 `monitor.py` 退出码 3（接口结构性变更）会**立即终止并失败**，让 GitHub 发失败邮件（哨兵保留）。
- 公开仓库 Actions 分钟数不限，本方案零额外费用。

> **可选加固**：cron-job.org 每 5 分钟 POST `workflow_dispatch` 作外部备份（免费，需注册；配置：URL=`https://api.github.com/repos/leslie0304/huashan-slot-monitor/actions/workflows/monitor.yml/dispatches`，POST，Header 含 `Authorization: Bearer <PAT>` + `Content-Type: application/json`，body `{"ref":"main"}`）。非必需——自建循环已独立成立。

## 放号窗口高频监测（17:35–18:10）

华山预约页面曾公告「10-15 18:00 开始抢新一轮预约」。放号时刻号源秒光（0→1→0→1 反复抖动），5 分钟节奏极易整轮错过。对策：

- **窗口内自动提频**：monitor.py 落入放号窗口后，在单次 run 内自行以 **60 秒/轮**内循环盯到窗口结束（无需外部改 cron）；
- **冷却缩短为 3 分钟**：放号时段号源抖动快，缩短上升沿连报间隔，不漏不掉；
- **17:55 到点预警**：窗口开始前 5 分钟发一条【放号预警】，请陛下提前打开公众号就位；
- **日期定制**：收到预约页面新的放号公告后，用环境变量 `RELEASE_WINDOWS` 传当日窗口（`date` 填 `YYYY-MM-DD` 则仅当日生效），例如：

```bash
RELEASE_WINDOWS='[{"start":"17:35","end":"18:10","interval":60,"headsup":"17:55","cooldown":3,"label":"10-20晚间放号","date":"2026-10-20"}]' python monitor.py
```

## 门诊前夜提醒（20:00 查退号 / 挂候补）

门诊前一天晚 20:00 是退号/弃号高峰。monitor.py 按医生排班（周一=0）自动推导提醒日：

| 提醒日 | 明日门诊 | 提醒内容 |
|---|---|---|
| 周一 20:00 | 周二：齐思思（皮肤科·上午） | 刷目标医生页面，有号直接约；约满立刻挂候补 |
| 周三 20:00 | 周四：齐思思（下午）+ 周丽诺（内分泌科·上午/下午） | 同上 |

### 前夜退号高频窗口（20:00–23:30）

次日门诊的退号一般在**晚 8 点后**陆续放出（18:00 那轮是新号放号，不是退号，两回事）。故提醒日当晚自动进入内循环高频监测：

- **时段**：20:00–23:30（按门诊日倒推周一/周三，与 17:35–18:10 放号窗时段不重叠）；
- **节奏**：约 3 分钟一轮，上升沿（0→有号）即推【抢号】 alert，冷却 5 分钟；
- **额度**：窗口内出现的真号源计入放号提醒（sent），与 20:00 提醒等服务消息**共享每日 5 条**；额度满时优先保放号提醒；
- **23:30 后**：退号极少，且已挂候补的用户系统会自动补位，无需守着刷新。

提醒与窗口内的 alert 均为服务/放号类消息，**共享每日 5 条总额度**；额度满时优先保放号提醒，服务消息自动跳过。

## 保活通知（心跳）

为区分「真没号」与「监测器断联」，monitor.py 在**北京时间 12:00 前后**报「上午时段」、**18:00 前后**报「下午时段」平安简报，内容含本时段放号提醒次数：

- 收到 = 系统正常存活；若本时段 0 次提醒，说明暂无号源（非断联）。
- **未收到** = 监测器可能断联，请检查 GitHub Actions 运行状态 / cron-job.org 任务是否启用。
- 心跳属服务类消息，与放号提醒**共享每日 5 条总额度**（Server酱免费版为总上限）；额度满时优先保放号提醒。

## 候补机制

约满后在医院 App 点「候补」即进入排队，有人退号系统**自动补位**，无需手动刷新。本监测器只报「可直接预约」的号源（放号新释放 + 候补未覆盖的瞬时弃号）。

## 注意事项

- 号数为 114 聚合值，可能含特需（600 元）/ 涉外档或其它班次，具体班次与价格请以 App 内显示为准。
- 接口一旦变更/失效，连续 3 轮结构异常 → workflow 以非零码失败 → GitHub 向仓库管理员发邮件（天然哨兵）。**连续 3 轮才判死**是为容忍放号峰值的瞬时超时/空响应（10-16 18:00 实测被 114 峰值打瘫，一击致命会错失整个窗口）。
- 公开仓库 60 天无活动，`scheduled` 会自动禁用；每月手动 `workflow_dispatch` 一次即可保活。
- 免费版 Server酱 5 条/天为**总上限**：内置**上升沿提醒**（仅在号源从 0 变为有号时推送，持续有号不再重复）+ 15 分钟连报冷却（放号窗口内 3 分钟、前夜退号窗口内 5 分钟）+ 每日 5 条硬顶；放号提醒（含前夜退号窗口）、平安简报、放号预警、门诊前夜提醒**共享这 5 条**，额度满时服务消息自动跳过、放号提醒优先。不够可订阅 39 元/年（1000 条/天）。
- 公开仓库 60 天无活动，`scheduled` 会自动禁用；每月手动 `workflow_dispatch` 一次或保持 cron-job.org 活跃即可保活。
